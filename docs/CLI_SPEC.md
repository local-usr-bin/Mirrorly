# Mirrorly CLI 规范 v1.0

> 状态：已确认 · 日期：2026-09-12
> 本文件是 CLI 的契约文档：命令结构、参数、退出码。实现须与本规范一致；变更需先修订本文档。

## 0. 总则

- 入口：`mirrorly <command> [options]`（`python -m mirrorly` 等价）。
- 全局选项：`--config <path>`（指定配置目录，默认 `./.mirrorly` 或 `%USERPROFILE%/.mirrorly`，MVP 实现其一即可）、`--task <name>`（指定任务；MVP 单任务时可省略，多任务时必填）、`--quiet / --verbose`、`--no-color`。
- 所有破坏性操作（restore 覆盖、init 已有仓库）必须显式确认或 `--yes` 跳过。
- 输出约定：人读输出到 stdout；`--json` 时输出机器可读 JSON（为 GUI 预留）；错误信息到 stderr。
- 备份/校验报告（M9）除终端摘要外，写入目标仓库 `logs/` 目录。

---

## 1. `mirrorly init`

初始化备份仓库（目标目录）与任务配置。

| 参数 | 说明 |
| --- | --- |
| `--source <dir>` | 备份源目录（必填） |
| `--target <dir>` | 备份目标根目录（必填，其下创建 `MirrorlyRepo/`） |
| `--filesystem-policy <strict\|warn>` | 非 NTFS 目标的策略，默认 `strict`（D2 确认：exFAT 明确提示，用户决定继续或转 NTFS；`warn` 模式下用户确认后以整文件复制运行，报告中标注降级） |
| `--yes` | 跳过交互确认 |

行为：检测目标文件系统 → 写入 `repo.json`（格式版本、卷标识、哈希算法）→ 生成 `config.d/<task>.toml` → 输出摘要。
幂等：目标已是仓库则报错（除非 `--yes` 下明确重新初始化，MVP 可直接报错拒绝）。

---

## 2. `mirrorly backup`

执行一次备份，生成新快照。

| 参数 | 说明 |
| --- | --- |
| `--dry-run` | 只输出变更预览（新增/修改/删除统计与列表），不写入任何内容（M8） |
| `--full-hash` | 跳过元数据初筛，全量哈希比对（ADR-006 的严格模式，慢） |
| `--exclude <pattern>` | 追加排除规则（可重复），与配置合并 |
| `--yes` | 跳过确认（用于计划任务/脚本） |

行为：任务锁 → 卷标识校验 → 扫描源 → 与最近 manifest 对比 → dry-run 输出或执行复制（临时文件+原子改名、写入即校验）→ 写 manifest（incomplete→complete）→ 按保留策略清理 → 输出报告。
中断恢复：若发现 incomplete manifest，提示并以其为基线续传（TR-5）。

---

## 3. `mirrorly verify`

校验备份完整性。

| 参数 | 说明 |
| --- | --- |
| `--snapshot <id>` | 只校验指定快照（默认校验最近一个） |
| `--all` | 校验所有快照 |
| `--quick` | 只校验 manifest 一致性与文件存在性，不重算哈希 |

行为：按 manifest 重算目标文件哈希并比对；输出逐项差异与总结论。

---

## 4. `mirrorly restore`

从快照恢复文件。

| 参数 | 说明 |
| --- | --- |
| `--snapshot <id>` | 指定快照（默认最近一个 complete 快照） |
| `--to <dir>` | 恢复目标目录（必填；不允许直接覆盖源目录，除非 `--in-place`） |
| `--in-place` | 恢复回原始源路径（危险操作，需 `--yes` 且逐项提示覆盖） |
| `--path <pattern>` | 只恢复匹配的文件/子树（可重复） |
| `--overwrite <never\|older\|always>` | 目标已存在时的策略，默认 `never`（TR-4：防覆盖用户新数据） |

行为：列出将恢复的文件与覆盖情况 → 确认 → 复制恢复 → 报告。恢复产物为普通文件，不需要 verify。

---

## 5. `mirrorly list`

列出快照。

| 参数 | 说明 |
| --- | --- |
| `--json` | JSON 输出 |
| `--verbose` | 显示每快照统计（文件数、总大小、增量大小、状态） |

行为：读 `manifests/` 目录列出全部快照（id、时间、状态 complete/incomplete、统计），按时间排序。incomplete 快照明确标注。

---

## 6. 退出码规范

| 码 | 含义 | 典型场景 |
| --- | --- | --- |
| 0 | 成功 | 全部完成，无跳过项 |
| 1 | 一般错误 | 未捕获异常、IO 错误、磁盘满 |
| 2 | 用法错误 | 参数缺失/非法（argparse 约定） |
| 3 | 部分完成 | 备份完成但有文件被跳过（锁定、权限、读取中变动）——报告列出明细 |
| 4 | 校验失败 | verify 发现哈希不匹配/文件缺失 |
| 5 | 目标身份不符 | 卷标识不匹配（盘符漂移/插错盘，M10）；仓库格式版本不兼容 |
| 6 | 用户中止 | 交互确认中拒绝；任务锁被占用（另一实例运行中） |
| 130 | Ctrl+C | 遵循 Unix 约定 |

脚本约定：`backup` 用 0/3 区分"干净完成"与"有跳过"，计划任务场景应对 3 发提醒而非视为失败。

---

## 7. 明确不做的命令（v1）

- 不设 `sync`（W1）、不设 `mount`/`browse`（超出 MVP）、不设守护/监控类命令（W5）、不提供 `config edit` 等配置管理命令（手改 TOML 即可，保持 CLI 面最小）。
