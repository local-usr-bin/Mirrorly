# Mirrorly 技术风险分析

> 版本：v1.0 · 日期：2026-09-12 · 依据：PRD v0.2（决策 D1–D7 已定案）
> 每项风险包含：描述、影响、设计对策、验证方式。风险等级：高/中/低。

---

## TR-1 文件变化检测（等级：中）

**描述**：如何准确发现源目录中新增/修改/删除/重命名的文件。
- mtime 陷阱：某些编辑器/工具写文件后回写 mtime，或 FAT/exFAT 源端时间精度低（2 秒粒度），导致"内容变了但元数据没变"漏检；
- 时钟问题：系统时间被修改、夏令时、跨设备拷贝带来的 mtime 错乱；
- 重命名无法被元数据识别，会被当作"删除+新增"重传。

**影响**：漏备个别文件（数据安全风险）；或误判变更导致无谓全量重传（性能问题）。

**设计对策（对应 D5）**：
- 清单记录（路径、大小、mtime、首次哈希）；大小或 mtime 变化 → 哈希复核后才判定变更；
- 大小未变且 mtime 未变的文件默认信任；提供 `--strict`（后续增强）做全量哈希兜底；
- 重命名 v1 不优化（按删除+新增处理，硬链接机制下只是多一次拷贝，功能正确）。

**验证方式**：构造单元测试——改内容不改 mtime、改 mtime 不改内容、大小相同内容不同、重命名四类用例。

## TR-2 增量备份（等级：中）

**描述**：增量判断错误会污染快照；硬链接管理错误会损坏历史快照。
- 关键不变量：**旧快照一旦被创建就永不修改**。若误对已硬链接的文件做"原地写入"，会同时改掉所有历史版本（硬链接共享同一 inode）——这是最危险的一类 bug；
- Windows 上硬链接数有上限（1024），快照数接近上限时会失败。

**设计对策（对应 D2）**：
- 变更文件一律"写入新临时文件 → 原子替换/原子改名"，**绝不原地写**已链接文件；
- 快照数受保留策略限制（默认 30 + 每月 1 个），远低于 1024 上限；代码中对 `os.link` 失败做显式报错而非忽略；
- 清单（manifest）与快照目录一一对应，快照完成前清单标记为 incomplete，下次运行忽略之。

**验证方式**：集成测试——修改某文件后确认旧快照中该文件内容不变；检查硬链接计数正确。

## TR-3 数据完整性校验（等级：中）

**描述**：
- 写入目标盘过程中的位错误（USB 链路、外置盘坏块）；
- 外置盘长期存放的静默损坏（bit rot），数月后才发现快照已坏；
- 校验本身的成本：对 TB 级数据全量哈希耗时可观。

**设计对策（对应 D7）**：
- 每个文件复制后立即对目标端重算哈希并与源端比对，失败即标记该文件失败、不进入完成清单；
- 清单中持久化每个文件的哈希，`verify` 命令支持对指定快照做全检（后续可加抽检）；
- 哈希算法：BLAKE3 为主、`blake3` 不可用时降级 SHA-256（ADR-013 已冻结）；xxHash 不用于完整性校验（非密码学哈希，不抗构造碰撞）；算法名记录于 repo.json 与清单，同一仓库内不混用。

**验证方式**：测试环境手动篡改目标文件后运行 verify 应检出；复制期间注入 IO 错误应报告失败文件。

## TR-4 冲突处理（等级：低）

**描述**：单向备份天然规避了双向同步的冲突合并，但仍有残余冲突场景：
- 备份运行期间源文件正被修改（读到撕裂内容）；
- 恢复（restore）时目标位置已存在同名文件；
- 同一源目录被两个备份任务同时写入（MVP 单任务下不存在，多任务预留时需考虑）。

**设计对策**：
- 复制时若文件大小/mtime 在读取过程中发生变化，视为"变动中文件"，本次跳过并列入报告，下次备份自然收敛；
- restore 默认拒绝覆盖已存在文件，需显式 `--overwrite`；
- 任务级锁文件（lockfile）防止同一配置并发运行。

**验证方式**：测试——备份中途修改源文件、restore 到已占用位置、双进程同时启动。

## TR-5 中断恢复（等级：高，用户场景最敏感）

**描述**：断电、拔盘、进程被杀都可能发生在备份中途。
- 半成品文件留在目标端会被误认为备份成功；
- 快照目录结构半建状态污染后续增量判断；
- 外置盘突然被拔掉时 IO 错误处理不当可能卡死或产生误导性报错。

**设计对策（对应 M7）**：
- 所有文件写入走 `临时文件（.mirrorly-tmp-*）→ fsync → 原子重命名` 三步；
- 快照清单最后一步才写入"完成"标记；启动时扫描 incomplete 快照并清理；
- 重跑即续传：已完整存在于新快照路径的文件（大小+哈希一致）直接复用，未完成部分重新复制；
- 对目标盘不可达（盘未插入/断开）给出明确错误信息而非通用异常。

**验证方式**：故障注入测试——复制到一半杀进程/卸载测试盘，重跑后快照完整、无 tmp 残留、校验通过。

## TR-6 大文件处理（等级：中）

**描述**：P2 画像单文件可达数 GB（视频工程、RAW 连拍包、虚拟机镜像）。
- 一次性读入内存不可行；
- 拷贝耗时长，中断概率高；
- Windows 路径长度限制（260 字符 MAX_PATH）在深层目录 + 快照路径叠加时容易触顶；
- 文件被独占锁定（Outlook PST、数据库文件）无法读取。

**设计对策**：
- 流式分块读写（如 4–8 MB 缓冲），哈希增量计算，内存占用与文件大小无关；
- 断点信息可记录到临时清单，重跑时对未完成大文件可续传（v1 可简化为整文件重传，续传列增强项）；
- 启用 Windows 长路径支持（`\\?\` 前缀）并在文档中说明系统组策略要求；
- 锁定文件：读取失败即列入报告跳过，不中断整体；后续评估 VSS 卷影复制。

**验证方式**：测试 8GB+ 文件的备份/校验/中断重跑；内存占用监控（应恒定）；长路径用例。

## TR-7 外部硬盘场景（等级：高，主战场）

**描述**：外置盘是 MVP 主目标，坑最多：
- 盘符漂移：同一物理盘今天 D:\ 明天 E:\，按盘符寻址会写错位置甚至写满系统盘；
- 文件系统多样：exFAT 无硬链接、无权限、时间精度 2 秒；FAT32 单文件 4GB 上限；
- 不安全拔出导致文件系统脏状态；
- USB 供电/休眠导致写入中途掉线；
- 目标盘空间耗尽。

**设计对策（对应 M10、D2 修订）**：
- 目标盘按**卷序列号 + 卷标**双重识别，配置中记录卷标识而非盘符；识别不到时明确报错"请连接备份盘"，绝不写到替代位置；
- 初始化时检测文件系统：NTFS 完整支持；exFAT/FAT32 明确提示能力限制（无硬链接、快照空间线性增长、FAT32 另有 4GB 单文件限制），用户显式选择继续或转换 NTFS，**不静默降级**（已确认决策）；
- 备份前预估所需空间（dry-run 统计），剩余空间 < 预估值 ×1.1 时提前报错；
- 每个快照完成后 fsync 目录并提示"可安全移除"；文档建议配合系统"安全删除硬件"；
- 写盘期间禁用系统对该盘的节能休眠不可行时，至少在复制循环中保持活动 IO。

**验证方式**：真实外置盘端到端测试——换 USB 口盘符变化后重跑、备份中拔盘、写满小容量盘、exFAT 盘初始化提示流程。

## 汇总与结论

| 编号 | 风险 | 等级 | 核心对策 |
| --- | --- | --- | --- |
| TR-1 | 变化检测 | 中 | 元数据初筛 + 疑似项哈希复核 |
| TR-2 | 增量/硬链接 | 中 | 旧快照只读不变量 + 原子替换 |
| TR-3 | 完整性 | 中 | 写入即校验 + verify 全检 |
| TR-4 | 冲突 | 低 | 变动中跳过 + restore 防覆盖 + 任务锁 |
| TR-5 | 中断恢复 | 高 | 临时文件+原子改名+incomplete 清单+重跑续传 |
| TR-6 | 大文件 | 中 | 流式分块 + 长路径 + 锁定跳过 |
| TR-7 | 外置盘 | 高 | 卷标识寻址 + 文件系统明示策略 + 空间预估 |

**总体判断**：风险集中在 TR-5 与 TR-7，二者都可通过"原子写入 + 不变量清单 + 卷标识寻址"三条设计纪律系统性化解，不需要引入重量级架构。现有技术选型（Python + NTFS + 硬链接快照）足以覆盖，无阻塞性风险。
